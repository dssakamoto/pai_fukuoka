# 要件定義書: 言葉で片付けてくれる SO-101 (v1 / v2)

Physical AI 「AI×ロボティクスによる創造的タスクの実現」。

## 1. 目的

自然言語の指示(例:「赤いブロックを箱に入れて」)を VLM で解釈し、SO-101 が pick & place を実行する。
v1 はシミュレーション(MuJoCo)で完結させ、実機(SO-101)へ差し替え可能な構造にする。
v2 では実機で SmolVLA を微調整し、IK による実行部分と比較する。v2 の要件は 13 節に記載する。

## 2. スコープ

### 2.1 v1 の対象

- MuJoCo 上の SO-101 によるシミュレーション
- VLM によるカメラ画像からの対象物・置き場所の特定
- 画像座標と深度から3次元位置への変換
- IK による把持・運搬・配置
- 成功率の自動評価と動画の録画
- ノード分割(dora-rs)、環境固定(uv / Docker)、LeRobot 形式での実行記録

### 2.2 v1 の対象外

- 実機での動作(設計上の差し替え口のみ用意する)
- SmolVLA の学習・推論(v2)
- ROS 2 対応(任意。レポートに移植方針を記載するのみ)

## 3. 前提と制約

| 項目 | 内容 |
|---|---|
| ロボット | SO-101 のみ(フォロワーアームとリーダーアーム) |
| シミュレータ | MuJoCo。モデルは公式 `TheRobotStudio/SO-ARM100` の `Simulation/SO101` |
| 開発環境 | macOS (Apple Silicon)、GPU なし |
| 言語 | Python |
| VLM | Anthropic / OpenAI / Gemini / Gemma を設定で切り替えて使う。API キーは環境変数で渡し、コードに含めない |
| ROS | 必須としない |
| 提出物 | 動画(1〜3分、2倍速まで可。倍速の場合は動画内とレポートに明記)、コード一式、レポート |
| ライセンス | SO-101 モデル(SO-ARM100 リポジトリ)を含む、利用する OSS・モデルのライセンスを確認し、README に記載する |

## 4. 機能要件

要件は EARS 記法で記述する。

| ID | 要件 |
|---|---|
| FR-01 | システムは、シミュレーション内に SO-101、色違いのブロック複数、箱、固定カメラ(RGB と深度)を持つシーンを生成しなければならない。 |
| FR-02 | ユーザーが自然言語の指示を入力したとき、システムは、カメラ画像と指示を VLM に渡し、対象物と置き場所の画像上の位置を構造化データ(JSON)で受け取らなければならない。 |
| FR-02a | システムは、VLM を `VlmClient` 抽象インターフェース(画像と指示を入力し、共通スキーマの検出結果を返す)の背後に置き、Anthropic、OpenAI、Gemini、Gemma の各実装を設定(プロバイダ名とモデル名)のみで切り替えられなければならない。 |
| FR-02b | プロバイダごとに座標の表現(絶対ピクセル、0〜1000 の正規化など)が異なるとき、システムは、各実装の内部で共通形式(画像のピクセル座標)に変換して返さなければならない。 |
| FR-02c | Gemma は、Ollama(ローカル推論)経由で利用できなければならない。接続先(`base_url`)とモデル名は設定で指定し、Ollama の OpenAI 互換エンドポイントを使って OpenAI 用の実装と共通化してよい。Gemini API 経由の Gemma は v1 の対象外とする。 |
| FR-03 | VLM の出力が JSON として不正、または対象が見つからないとき、システムは、動作を実行せず理由を表示しなければならない。 |
| FR-03a | VLM の呼び出しがタイムアウト(暫定 30 秒)、レート制限、通信エラーになったとき、システムは、間隔を空けて最大 2 回再試行し、それでも失敗したら動作を実行せず、失敗として記録しなければならない。 |
| FR-04 | 対象位置を受け取ったとき、システムは、深度とカメラパラメータからロボット座標系の3次元位置を算出しなければならない。 |
| FR-05 | 3次元位置を得たとき、システムは、IK により接近・把持・持ち上げ・移動・解放の関節軌道を生成して実行しなければならない。 |
| FR-06 | IK が解を得られない、または関節可動域を超えるとき、システムは、動作を実行せずエラーを返さなければならない。 |
| FR-07 | 動作が完了したとき、システムは、次の条件をすべて満たす場合を成功と判定しなければならない。(1) 指定したブロックの中心が、水平方向で箱の内寸の内側にある。(2) ブロックの中心の高さが、箱の縁より低い。(3) 解放後 1 秒の時点で、ブロックの速度がしきい値(暫定 1 cm/s)以下である。 |
| FR-08 | システムは、`Robot` 抽象インターフェース(関節指令の送信と状態取得)の背後に実装を隠し、`SimRobot` と `So101Robot` を設定で切り替えられなければならない。 |
| FR-09 | システムは、実行ごとに画像・関節状態・指示・VLM 出力・結果を LeRobot 形式で記録しなければならない。 |
| FR-10 | システムは、実行をレンダリングして動画ファイルに保存できなければならない。 |
| FR-11 | システムは、実行部分を `Policy` インターフェースの背後に置き、IK 版と(v2 の)SmolVLA 版を差し替えられなければならない。 |
| FR-12 | システムは、ブロックの初期配置と指示を変えた複数試行を自動実行し、成功率を出力しなければならない。初期配置は、ロボット前方の作業台上の 20 cm × 20 cm の範囲(暫定)に、ブロック同士を 5 cm 以上離してランダムに置く。箱の位置は v1 では固定とする。 |

## 5. 非機能要件

| ID | 要件 |
|---|---|
| NFR-01 | 再現性: `uv sync` と1コマンドでシミュレーションが起動できる。乱数シードを固定できる。 |
| NFR-02 | 安全性: 関節角・速度に上限を設け、実機では範囲外の指令を送らない(実機移行時の前提)。 |
| NFR-03 | 機密: API キーをリポジトリに含めない。キーは `ANTHROPIC_API_KEY`、`OPENAI_API_KEY`、`GEMINI_API_KEY` の環境変数から読み、`.env.example` に変数名のみを記載する。未設定のプロバイダを選んだ場合は、起動時に明確なエラーを出す。 |
| NFR-04 | 構成: ノードは dora-rs の dataflow.yml で配線し、ドライバの差し替えは設定のみで行える。 |
| NFR-05 | 品質: 座標変換・IK・成功判定・JSON 検証などの純粋ロジックに単体テストを書く。 |
| NFR-06 | 実行環境: GPU なしの Mac で、1試行(VLM の応答を含む)が 3 分以内(暫定)に完了する。 |
| NFR-07 | 実機の安全: 実機を動かす場合は、次を満たす。(1) キー操作 1 回でトルクを切る非常停止。(2) 初回の動作確認は、速度上限を通常の 30% 以下にする。(3) 作業範囲の外の目標位置は拒否する。(4) 通信が途絶えたら、その場で停止する。 |

## 6. 受け入れ基準(v1)

| ID | 基準 |
|---|---|
| AC-01 | 色の異なる3個のブロックで、指定した色を箱に入れる試行を 20 回実行し、成功率 70% 以上(暫定目標。実測後に見直す)。少なくとも1つのプロバイダでこれを満たす。 |
| AC-02 | 存在しない色を指定したとき、動作せず理由が表示される。 |
| AC-03 | `SimRobot` から `So101Robot` への切り替えが、設定変更のみで可能な構造になっている(実機接続は v1 の対象外)。 |
| AC-04 | API キーのあるプロバイダのそれぞれで、同一の画像・指示に対する検出結果を取得でき、設定変更のみで切り替わる。キーが無いプロバイダのテストはスキップし、レポートには「未評価」と記載する。 |
| AC-05 | プロバイダ別の検出誤差と成功率を、同一条件で比較した表をレポートに載せる。検出誤差は、VLM の出力から算出した3次元位置と、シミュレーション上の真の位置との距離(mm)とする。 |
| AC-06 | 1〜3分の動画に、指示・VLM の検出結果・実行・成功判定が映っている。倍速の場合は、動画内に明記されている。 |
| AC-07 | 単体テストが通り、対象ロジックのカバレッジが 80% 以上。 |
| AC-08 | レポートに、課題の概要、目的、システム構成、工夫した点、評価結果、講義内容との対応、今後の課題が書かれている。 |
| AC-09 | README の手順に従うと、新しい環境でシミュレーションと評価を再現できる。 |

## 9. 実装フェーズ

1. 雛形と MuJoCo 上の SO-101 の表示・関節駆動
2. ブロック・箱・カメラを置いたシーン
3. 座標変換と IK による固定位置の pick & place
4. VLM による対象特定の接続
5. 自動評価、動画、LeRobot 形式での記録
6. レポート、動画の整理
7. 実機用 `So101Robot` の実装(v1 の後半または v2 と合わせて)

## 10. リスク

| リスク | 対応 |
|---|---|
| 把持が不安定 | 大きめのブロック、摩擦・グリッパーの調整から始める |
| VLM の座標精度が低い | 検出の枠で出力させ、中心を取る。失敗時は再試行 |
| API 利用料・応答時間 | 1試行1回の呼び出しに抑える。結果をキャッシュして再現実験を可能にする |
| プロバイダ間で座標精度・出力形式が異なる | 共通スキーマと JSON 検証で吸収する。比較結果はレポートに記載する |
| Gemma は小型だと検出精度が低い可能性、画像非対応のサイズがある | 画像に対応するサイズを Ollama のモデル一覧で確認して選ぶ。モデルサイズを設定で選べるようにし、精度を実測する。低い場合は比較表に限界として記載する |
| ローカルモデルが Mac のメモリに収まらない | 小さいサイズに下げる。使用メモリを実測して記録する |
| モデル名・API 仕様の変更 | モデル名はコードに固定せず設定ファイルに置く。実装前に各公式ドキュメントで確認する |
| 実機とのずれ | 座標変換を `calibration` として分離する |

## 13. v2 要件

### 13.1 目的

v1 の IK による実行部分を、実機で収集したデモで微調整した SmolVLA に差し替え、同一条件で比較する。

### 13.2 機能要件

| ID | 要件 |
|---|---|
| FR-V2-01 | システムは、実機の SO-101 を `So101Robot` 経由で動かし、v1 と同じ指示で pick & place を実行できなければならない。 |
| FR-V2-02 | システムは、遠隔操作によるデモを LeRobot 形式で記録できなければならない。デモには、カメラ画像、関節状態、行動、言語指示を含める。遠隔操作には SO-101 のリーダーアームを使う(LeRobot のテレオペ機能)。 |
| FR-V2-03 | システムは、収集したデモで SmolVLA を微調整し、`Policy` インターフェースの実装として読み込めなければならない。 |
| FR-V2-04 | システムは、IK 版と SmolVLA 版を、同じ指示・同じ初期配置の範囲で実機評価し、成功率と所要時間を出力しなければならない。 |
| FR-V2-05 | システムは、デモの品質(欠損フレーム、時刻のずれ、関節値の範囲外)を学習前に検証し、不合格のデモを除外しなければならない(RoboOps ワークショップの内容)。 |

### 13.3 非機能要件

| ID | 要件 |
|---|---|
| NFR-V2-01 | 実機の安全要件 NFR-07 を満たす。 |
| NFR-V2-02 | 微調整の設定(データセット、ハイパーパラメータ、シード)を設定ファイルに残し、再現できる。 |
| NFR-V2-03 | 実機のシリアルポート(フォロワー・リーダーの2本)とカメラは udev で固定名にする(第3回の内容)。 |

### 13.4 受け入れ基準

| ID | 基準 |
|---|---|
| AC-V2-01 | デモを 50 本(暫定)以上収集し、検証を通過したものだけで微調整できている。 |
| AC-V2-02 | 実機で IK 版と SmolVLA 版をそれぞれ 10 回(暫定)試行し、成功率と所要時間の比較表をレポートに載せる。 |
| AC-V2-03 | SmolVLA 版の実機での成功率 50% 以上(暫定目標)。満たさない場合も、失敗の分析をレポートに載せれば v2 完了とする。 |
| AC-V2-04 | 試行中に非常停止が機能することを、実機で 1 回以上確認している。 |
