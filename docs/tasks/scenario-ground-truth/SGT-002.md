## タスク概要

`policy/` と `perception/` が `eval/` および `scene_spec` を(直接・推移とも)import していないことを、`ast` で import を走査するテストで保証する(FR-106, FR-401, US-005)。

- **後続タスク**: なし

## 完了条件

- [x] 実リポジトリで policy / perception が `so101_vlm.eval` と `so101_vlm.eval.scene_spec` を(推移込みで)import していない
- [x] `tmp_path` に作った「policy が eval を import する」合成パッケージでテストが失敗する(違反を検出する)
- [x] `from . import x` / `from .. import y` の相対 import も違反として検出する(`__init__.py` 内と通常モジュールで解決規則が違う点もテスト)
- [x] `if TYPE_CHECKING:` 内・関数内の遅延 import も検出する(型の上でも依存させない方針)
- [x] ファイルは `read_text(encoding="utf-8-sig")` で読み(BOM 付きでも `ast.parse` が落ちない)、CRLF でも検出する
- [x] `importlib.import_module` / `__import__` の文字列定数も検出。ガード対象自身の非定数の動的 import は検査不能として違反にする
- [x] 前方一致の罠(`evaluation_x` など eval で始まるだけの別名)を違反にしない。循環 import でも検査が終わる。失敗メッセージに経路が出る
