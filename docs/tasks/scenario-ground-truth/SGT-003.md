## 実施結果(2026-11-15 完了)

- コミット: `19f8bb6`(main に fast-forward でマージ済み。作業ブランチ・worktree は削除済み)
- テスト: `-m "not render and not api"` で 1919 passed(1864 + 新規 55)、3 skipped、カバレッジ 91.68%。`-m` なしの描画付き(`tests/test_scene.py` と `tests/eval`)も 487 passed
- 独立確認: 別モデル(opus)による計画レビュー(**致命的 1 件・推奨 8 件を計画に反映**)、メインでの差分レビュー、全体テストの再実行、変異テスト(サブエージェント 3 種 + メイン 3 種)
- 計画レビューで見つかった致命的な点: **ブロックの `<geom>` には `pos` 属性が無い**(MuJoCo の既定で 0 0 0)。「`pos` が 3 個の数値でなければエラー」と実装すると、`scene_spec` の import 時に eval 全体が壊れる。→ `pos` が無い要素は 0 0 0 として扱い、あるのに不正な場合だけエラーにした。メインの変異テスト M3 で、この誤りが import 時エラーになることも再現済み
- 補足: 丸め `round(x, 9)` は、現在の XML では不要(丸めなしでも完全一致)だが、将来の値の浮動小数点ノイズに対する保険
- XML の変更: `assets/scene_pickplace.xml` の冒頭コメント 1 行のみ(「scene_spec.py と一致させる」→「geometry.py が XML から読む」)。要素・属性は無変更

    camera_name: str; image_width: int; image_height: int                            # 🔵 XML 外の Python 定数
    @classmethod
    def from_xml(cls, path: Path = PICKPLACE_SCENE_PATH) -> "SceneGeometry": ...     # 🟡 ElementTree。pos 無しは 0 0 0。回転・class は ValueError
    @classmethod
    def from_model(cls, model: mujoco.MjModel) -> "SceneGeometry": ...               # 🟡 from_xml とは別の導出式

def get_geometry() -> SceneGeometry: ...                                             # 🟡 lru_cache

@dataclass(frozen=True)
class PlaceRegion:                                                                   # 🔵 目標と判定で共有。__post_init__ で検証
    center_xy: tuple[float, float]; inner_half_size: float; rim_z: float; floor_top_z: float
    @property
    def goal_xyz(self) -> tuple[float, float, float]: ...                            # (cx, cy, floor_top_z)

# src/so101_vlm/eval/scene_spec.py: camera_name / image_width / image_height / box_body_name も geometry から取る(追加)。work_area_x/y はリテラルのまま(SGT-013 で削除)
