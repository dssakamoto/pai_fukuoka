# 箱位置の掃引(SGT-012)

箱の位置を動かしても、成功判定・oracle・軌道計画が追従するかを確かめた結果。VLM は使わない(oracle = 真の配置から作った枠)ので、API 料金はかからない。

- 実行日: 2026-11-25
- 実行環境: GitHub Actions(ubuntu、osmesa のソフトウェア描画)。一時ワークフローで一度だけ実行(ブランチは削除済み)
- コマンド: `uv run python scripts/sweep_box.py --trials 10 --seed 0 --out <出力先>`(再現できる。描画が要る)
- 生の結果: [box-sweep.csv](box-sweep.csv)

## 読み方

- **箱の位置による劣化は見られない**。全点の「IK 失敗を除く成功率」は 90〜100% で、箱固定の基準(oracle 85%、`provider-comparison.md`)を下回る点はない。置きの失敗(箱に入らない・倒れる等)は 0 件で、成功判定が動いた箱に追従している。
- **差は誤差の範囲**。各点 10 試行なので、1 件の失敗が 10 ポイントに見える。90% の点と 100% の点の差は、この件数では有意とは言えない。
- **基準の 85% とは直接比較できない**。基準は箱固定・seed 0〜19 の 20 試行で、この掃引は点ごとに「ブロックが箱に近すぎる seed」を除いている(除いた数は表の右端。2〜15 個)。除外は箱に近いブロック配置を落とすので、成功しやすい方に偏る可能性がある。「掃引の全点が基準から大きく外れない」ことの確認としては足りるが、成功率そのものの改善を示すものではない。

## 限界

- **箱を動かせる範囲が狭い**。掃引の 9 点は x 0.18〜0.20、y 0.13〜0.18(約 2 cm × 5 cm)。理由は、箱の外周が収まる位置の領域が、安全フィルタの `workspace`(y ≤ 0.26)・IK・箱の壁とのすき間(1 mm)・ブロックの作業範囲との共存で、既定位置の周りに限られるため(`docs/tasks/scenario-ground-truth/overview.md` の「実測で分かったこと」)。
- 外周の判定は、1 cm 格子の中間点で外側の格子点を使う保守的な設計(`OUTLINE_EPS_M`)。0.005 m の格子で領域を再生成すれば窓は広がる可能性があるが、今回は行っていない(計算が約 4 倍かかる)。`workspace` は広げていない(安全の設定で、実機にも効くため)。
- 到達可能領域は、基準のブロック (0.25, 0) 1 つで計算した近似(中央に、基準ブロックの足元として箱を置けない穴がある。保守的な側)。
- oracle のみ。実際の VLM(OpenAI 等)で箱位置を変えた再評価は SGT-014(任意)。
