## ペルソナ

### ペルソナ1: 開発者 (本人)

- **役割**: 講義課題として提出するプロジェクトの作者 (学生)
- **目的**: 箱の位置を変えた評価ができ、判定や oracle が食い違わないこと。レポートの「汎化」「今後の課題」に使えること
- **技術レベル**: 中級

### ペルソナ2: レビュアー (講義の採点者)

- **役割**: 提出物の設計とテストを読んで採点する
- **目的**: 設計の意図 (真値と推定値の分離) がコードとテストから読み取れること
- **技術レベル**: 上級

## エピック1: 箱位置を変えられる配置生成

### US-001: 箱とブロックを同時に生成する 🔵

**私は** 開発者 **として**
**seed から箱とブロックの配置を制約つきで生成したい**
**そうすることで** 箱の位置を変えた評価を、重なりや到達不能のない配置で実行できる

- **関連要件**: FR-002, FR-010, FR-011, FR-103, FR-104
- **優先度**: Must Have
- **受入基準**: AC-002, AC-010, AC-011, AC-014, AC-015

### US-010: 箱固定の既定で結果が変わらない 🔵

**私は** 開発者 **として**
**箱固定のとき、同じ seed で従来と同じブロック配置・同じ成功率になってほしい**
**そうすることで** 既存の比較表 (`docs/notes/provider-comparison.md`) が壊れない

- **関連要件**: FR-101, FR-201, FR-404
- **優先度**: Must Have
- **受入基準**: AC-012, AC-018, AC-025

---

## エピック2: 箱に追従する判定・oracle

### US-002: 箱を動かしても判定と oracle が追従する 🔵

**私は** 開発者 **として**
**置き先を領域として扱い、判定・oracle・固定位置デモが同じ領域を見てほしい**
**そうすることで** 箱を動かしても成功判定が食い違わない

- **関連要件**: FR-005, FR-006, FR-102
- **優先度**: Must Have
- **受入基準**: AC-005, AC-006, AC-013

### US-011: VLM 版でも置く高さを形状から求める 🔵

**私は** 開発者 **として**
**VLM 試行の置く高さを固定値でなく箱形状から求めたい**
**そうすることで** xy は画像、高さは形状という役割分担が明確になる

- **関連要件**: FR-202
- **優先度**: Should Have
- **受入基準**: AC-019

---

## エピック3: 形状の単一情報源

### US-003: 形状を XML から読む 🔵

**私は** 開発者 **として**
**形状の数値を XML の名前付き geom から読み、Python に再掲したくない**
**そうすることで** XML と Python の食い違いを構造的になくせる

- **関連要件**: FR-001, FR-403
- **優先度**: Must Have
- **受入基準**: AC-001, AC-024

### US-006: 障害物を自動収集する 🔵

**私は** 開発者 **として**
**障害物をモデルのタグ/グループから自動収集したい**
**そうすることで** geom 名の手書き列挙の更新漏れがなくなる

- **関連要件**: FR-008
- **優先度**: Should Have
- **受入基準**: AC-008

### US-007: 作業範囲をロボットから導く 🔴

**私は** 開発者 **として**
**作業範囲をロボットの運動学から導いた到達可能領域にしたい**
**そうすることで** 手で決めた値 (3cm 外側など) に依存せず、シーン配置が到達可能領域に従う

- **関連要件**: FR-009, FR-103
- **優先度**: Should Have
- **受入基準**: AC-009, AC-014

---

## エピック4: 真値と観測の分離

### US-004: 方策が見る情報を型で制限する 🔵

**私は** レビュアー **として**
**方策が見てよい情報が `Observation` 型に限られ、真値は `GroundTruth` の 1 経路だけであることを確認したい**
**そうすることで** 真値と推定値の分離の意図をコードから読み取れる

- **関連要件**: FR-003, FR-004, FR-402
- **優先度**: Must Have
- **受入基準**: AC-003, AC-004, AC-023

### US-005: 依存の向きをテストで守る 🔵

**私は** レビュアー **として**
**`policy/` と `perception/` が `eval/` や `scene_spec` を import しないことをテストで確認したい**
**そうすることで** 設計の境界が実際に守られていると信頼できる

- **関連要件**: FR-106, FR-401
- **優先度**: Must Have
- **受入基準**: AC-017, AC-022

---

## エピック5: 評価とレポート

### US-008: 箱位置ごとの成功率を掃引する 🔴

**私は** 開発者 **として**
**箱位置を変えた成功率の掃引結果をレポートに載せたい**
**そうすることで** 「汎化」の節で箱位置への頑健性を示せる

- **関連要件**: FR-105, FR-301
- **優先度**: Must Have
- **受入基準**: AC-016, AC-020

### US-009: Evaluator を差し替え可能にする 🔵

**私は** 開発者 **として**
**成否判定を Protocol 化し sim 実装を使いたい**
**そうすることで** 将来の実機向け実装 (別 plan) に差し替えられる

- **関連要件**: FR-007
- **優先度**: Should Have
- **受入基準**: AC-007

### US-012: 実 API で再評価を確認する 🟡

**私は** 開発者 **として**
**任意で OpenAI による箱位置変更時の再評価を実行したい**
**そうすることで** oracle と実 VLM の差を確認できる (料金がかかるため必須にしない)

- **関連要件**: FR-302
- **優先度**: Could Have
- **受入基準**: AC-021
