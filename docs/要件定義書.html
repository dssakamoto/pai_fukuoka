言葉で片付けてくれる SO-101

「赤いブロックを箱に入れて」と話しかけると、AI がカメラ画像から対象を見つけ、ロボットアーム SO-101 が掴んで箱に入れる。まずシミュレーションで作り、あとで同じコードのまま実機に移す。

v1 シミュレーション · VLM + IK v2 実機 · SmolVLA 日程は仮
01

3つの問いで分かる概要

何を作り、どう作り、いつまでに終えるか。

WHAT · 何を作る
言葉の指示で、ブロックを箱に片付けるロボット

自然言語の指示(例:「赤いブロックを箱に入れて」)を VLM で解釈し、SO-101 が pick & place を実行する。

HOW · どう作る
AI が「見て決める」
計算で「動かす」

VLM(画像と言葉が分かる AI)が対象を見つけ、IK(逆運動学)で関節角を計算する。v2 では動作そのものも AI(SmolVLA)に任せて比較する。

WHEN · いつまでに
5 週間で提出
  • v1 完了2026-11-01
  • v2 完了2026-11-15
  • 提出2026-11-22

v1 SIMULATION

MuJoCo の中で完結する
  • VLM が画像から「どれを」「どこへ」を決める
  • IK で手先をそこへ運ぶ
  • 20 回試して成功率を測る
  • 4 つの VLM(Anthropic / OpenAI / Gemini / Gemma)を比べる

v2 REAL ROBOT

実機の SO-101 で動かす
  • リーダーアームで人がお手本を 50 本見せる
  • お手本で SmolVLA を追加学習する
  • IK 版と SmolVLA 版を実機で 10 回ずつ比べる
  • 間に合わなければ v1 のみで提出(v1 だけで課題は成立)

やること・やらないこと(v1)

やる
  • MuJoCo 上の SO-101 によるシミュレーション
  • VLM によるカメラ画像からの対象物・置き場所の特定
  • 画像座標と深度から3次元位置への変換
  • IK による把持・運搬・配置
  • 成功率の自動評価と動画の録画
  • ノード分割(dora-rs)、環境固定(uv / Docker)、LeRobot 形式での実行記録
やらない
  • 実機での動作(設計上の差し替え口のみ用意する)
  • SmolVLA の学習・推論(v2)
  • ROS 2 対応(任意。レポートに移植方針を記載するのみ)
02

まずはこの用語だけ

この文書を読むのに必要な言葉。カードにマウスを乗せると少し浮きます。

SO-101 ロボットアーム
机に置ける小型の 6 関節アーム。人が動かすリーダーと、その動きをまねるフォロワーの 2 台組。今回の唯一の実機
VLM Vision-Language Model
画像と言葉の両方が分かる AI。「この写真の赤いブロックはどこ?」に答えられる。役目: どれを掴み、どこへ置くか決める
IK 逆運動学
「手先をここに置きたい」から、各関節を何度曲げればよいかを逆算する計算。役目: 位置を関節角に変える
VLA / SmolVLA Vision-Language-Action
画像と言葉から、ロボットの動きを直接出す AI。SmolVLA は LeRobot で公開されている小型の VLA。役目: v2 で IK の代わりに動かす
MuJoCo 物理シミュレータ
重力や接触を計算する仮想の世界。実機を壊す心配なく試せる。役目: v1 の舞台
dora-rs 講義 第6回
処理を小さなプログラム(ノード)に分けて、データを流してつなぐ仕組み。ROS 2 の考え方に近い。役目: 部品どうしをつなぐ配線
LeRobot 講義 第5回
Hugging Face のロボット学習ライブラリ。SO-101 のドライバ、データの保存形式、学習をまとめて扱う。役目: 実機の操作と記録
テレオペ 遠隔操作
人がリーダーアームを手で動かし、フォロワーが同じ動きをする。その様子を記録したものが「お手本(デモ)」。役目: v2 の学習データ集め
深度 Depth
カメラから物体までの距離。画像上の 1 点を、3 次元の位置に戻すのに使う。役目: 2D → 3D
受け入れ基準 AC
「これを満たせば完成」と判定する条件。ID は AC-01 のように付ける。役目: 完成の物差し

しくみ: 指示から動作まで 8 ステップ

カードを押すか「次へ」で 1 つずつ進みます。v2 に切り替えると、通らない道が薄くなります。

    
      
    
      
    sim と実機の切り替えは、camera と robot の 2 つだけを設定ファイルで差し替える。ほかの部品はそのまま使う。
    
    
    
  
    

  
    
    
    
      
    04
    画像の「点」を、ロボットの「位置」に変える
    VLM が返すのは画像上のピクセル。ロボットが欲しいのは自分から見た 3 次元の位置。その橋渡しをする。
    
      
    
        
    
          
          
    数値はイメージ。sim ではシーン定義からカメラの位置が分かるので、変換行列を自動で作れる。
    
        
    
        
      
          
    1. 画像上の点を取るVLM が返した枠の中心ピクセル (u, v)。外れ値を避けるため、枠の中の深度は中央値を使う。
      2. 
          
    2. 深度でカメラからの 3D 位置に戻すカメラの内部パラメータ(焦点距離・中心)を使い、「カメラから見てどこか」を計算する。
      3. 
          
    3. ロボットの根元から見た位置に直すカメラ → ロボット根元の変換行列(calibration.yaml)を掛ける。実機ではここを計測して入れ替える。
      4. 
        
    
      
    
    
    
  
    

  
    
    
    
      
    05
    4 つの VLM を、同じ形にそろえて使う
    会社ごとに座標の返し方が違う。各実装の中で共通の形(画像のピクセル座標)に変換するので、後ろの部品は気にしなくてよい。
    
      
    
        
    
        
    
          
    プロバイダの返事(例)
    
          
    →
    
          
    共通形式 bbox_px [x1, y1, x2, y2]
    
        
    
        
    
        
    出力形式は説明用の例。モデル名・座標の形式は、実装時に各社の公式ドキュメントと実測で確認する(タスク T-16)。API キーは環境変数で渡し、コードには書かない。
    
      
    
    
    
  
    

  
    
    
    
      
    06
    「成功」の決め方
    3 つの条件を全部満たしたときだけ成功。ボタンで状況を切り替えて確かめられます。
    
      
    
        
    
          
        
    
        
    
          
    
            
            
            
            
          
    
          
      
            
    • ?① 水平方向: ブロックの中心が箱の内寸の内側
      • 
            
    • ?② 高さ: ブロックの中心が箱の縁より低い
      • 
            
    • ?③ 静止: 放して 1 秒後の速さが 1 cm/s 以下
      • 
          
    
          
    
          
    FR-07。しきい値は暫定。失敗はさらに「VLM 失敗 / IK 失敗 / 掴み失敗 / 置き失敗」に分けて記録する。
    
        
    
      
    
    
    
  
    

  
    
    
    
      
    07
    実機を動かす前の安全ルール
    NFR-07。シミュレーションでも同じフィルタを通し、実機で初めて試すことがないようにする。
    
      
    
        
    ⏻
    非常停止
    キー操作 1 回でモーターの力(トルク)を切る。
    
        
    🐢
    最初はゆっくり
    初回の動作確認は、速度の上限を通常の 30% 以下にする。
    
        
    ▢
    作業範囲の外は拒否
    決めた箱型の範囲の外へ行こうとする指令は送らない。
    
        
    ⚡
    通信が切れたら止まる
    状態が一定時間届かなければ、その場で停止する。

    要件の一覧(v1)
    ここが要件定義書の本体。開くと表が出ます。
    
      
    前提と制約8 項目
    項目内容
    ロボットSO-101 のみ(フォロワーアームとリーダーアーム)
    シミュレータMuJoCo。モデルは公式 TheRobotStudio/SO-ARM100 の Simulation/SO101
    開発環境macOS (Apple Silicon)、GPU なし
    言語Python
    VLMAnthropic / OpenAI / Gemini / Gemma を設定で切り替えて使う。API キーは環境変数で渡し、コードに含めない
    ROS必須としない
    提出物動画(1〜3分、2倍速まで可。倍速の場合は動画内とレポートに明記)、コード一式、レポート
    ライセンスSO-101 モデル(SO-ARM100 リポジトリ)を含む、利用する OSS・モデルのライセンスを確認し、README に記載する
    
      
    機能要件 FR(何ができるか)16 件
    ID要件
    FR-01システムは、シミュレーション内に SO-101、色違いのブロック複数、箱、固定カメラ(RGB と深度)を持つシーンを生成しなければならない。
    FR-02ユーザーが自然言語の指示を入力したとき、システムは、カメラ画像と指示を VLM に渡し、対象物と置き場所の画像上の位置を構造化データ(JSON)で受け取らなければならない。
    FR-02aシステムは、VLM を VlmClient 抽象インターフェース(画像と指示を入力し、共通スキーマの検出結果を返す)の背後に置き、Anthropic、OpenAI、Gemini、Gemma の各実装を設定(プロバイダ名とモデル名)のみで切り替えられなければならない。
    FR-02bプロバイダごとに座標の表現(絶対ピクセル、0〜1000 の正規化など)が異なるとき、システムは、各実装の内部で共通形式(画像のピクセル座標)に変換して返さなければならない。
    FR-02cGemma は、Ollama(ローカル推論)経由で利用できなければならない。接続先(base_url)とモデル名は設定で指定し、Ollama の OpenAI 互換エンドポイントを使って OpenAI 用の実装と共通化してよい。Gemini API 経由の Gemma は v1 の対象外とする。
    FR-03VLM の出力が JSON として不正、または対象が見つからないとき、システムは、動作を実行せず理由を表示しなければならない。
    FR-03aVLM の呼び出しがタイムアウト(暫定 30 秒)、レート制限、通信エラーになったとき、システムは、間隔を空けて最大 2 回再試行し、それでも失敗したら動作を実行せず、失敗として記録しなければならない。
    FR-04対象位置を受け取ったとき、システムは、深度とカメラパラメータからロボット座標系の3次元位置を算出しなければならない。
    FR-053次元位置を得たとき、システムは、IK により接近・把持・持ち上げ・移動・解放の関節軌道を生成して実行しなければならない。
    FR-06IK が解を得られない、または関節可動域を超えるとき、システムは、動作を実行せずエラーを返さなければならない。
    FR-07動作が完了したとき、システムは、次の条件をすべて満たす場合を成功と判定しなければならない。(1) 指定したブロックの中心が、水平方向で箱の内寸の内側にある。(2) ブロックの中心の高さが、箱の縁より低い。(3) 解放後 1 秒の時点で、ブロックの速度がしきい値(暫定 1 cm/s)以下である。
    FR-08システムは、Robot 抽象インターフェース(関節指令の送信と状態取得)の背後に実装を隠し、SimRobot と So101Robot を設定で切り替えられなければならない。
    FR-09システムは、実行ごとに画像・関節状態・指示・VLM 出力・結果を LeRobot 形式で記録しなければならない。
    FR-10システムは、実行をレンダリングして動画ファイルに保存できなければならない。
    FR-11システムは、実行部分を Policy インターフェースの背後に置き、IK 版と(v2 の)SmolVLA 版を差し替えられなければならない。
    FR-12システムは、ブロックの初期配置と指示を変えた複数試行を自動実行し、成功率を出力しなければならない。初期配置は、ロボット前方の作業台上の 20 cm × 20 cm の範囲(暫定)に、ブロック同士を 5 cm 以上離してランダムに置く。箱の位置は v1 では固定とする。
    
      
    非機能要件 NFR(どの品質で)7 件
    ID要件
    NFR-01再現性: uv sync と1コマンドでシミュレーションが起動できる。乱数シードを固定できる。
    NFR-02安全性: 関節角・速度に上限を設け、実機では範囲外の指令を送らない(実機移行時の前提)。
    NFR-03機密: API キーをリポジトリに含めない。キーは ANTHROPIC_API_KEY、OPENAI_API_KEY、GEMINI_API_KEY の環境変数から読み、.env.example に変数名のみを記載する。未設定のプロバイダを選んだ場合は、起動時に明確なエラーを出す。
    NFR-04構成: ノードは dora-rs の dataflow.yml で配線し、ドライバの差し替えは設定のみで行える。
    NFR-05品質: 座標変換・IK・成功判定・JSON 検証などの純粋ロジックに単体テストを書く。
    NFR-06実行環境: GPU なしの Mac で、1試行(VLM の応答を含む)が 3 分以内(暫定)に完了する。
    NFR-07実機の安全: 実機を動かす場合は、次を満たす。(1) キー操作 1 回でトルクを切る非常停止。(2) 初回の動作確認は、速度上限を通常の 30% 以下にする。(3) 作業範囲の外の目標位置は拒否する。(4) 通信が途絶えたら、その場で停止する。
    
      
    受け入れ基準 AC(完成の物差し)9 件
    ID基準
    AC-01色の異なる3個のブロックで、指定した色を箱に入れる試行を 20 回実行し、成功率 70% 以上(暫定目標。実測後に見直す)。少なくとも1つのプロバイダでこれを満たす。
    AC-02存在しない色を指定したとき、動作せず理由が表示される。
    AC-03SimRobot から So101Robot への切り替えが、設定変更のみで可能な構造になっている(実機接続は v1 の対象外)。
    AC-04API キーのあるプロバイダのそれぞれで、同一の画像・指示に対する検出結果を取得でき、設定変更のみで切り替わる。キーが無いプロバイダのテストはスキップし、レポートには「未評価」と記載する。
    AC-05プロバイダ別の検出誤差と成功率を、同一条件で比較した表をレポートに載せる。検出誤差は、VLM の出力から算出した3次元位置と、シミュレーション上の真の位置との距離(mm)とする。
    AC-061〜3分の動画に、指示・VLM の検出結果・実行・成功判定が映っている。倍速の場合は、動画内に明記されている。
    AC-07単体テストが通り、対象ロジックのカバレッジが 80% 以上。
    AC-08レポートに、課題の概要、目的、システム構成、工夫した点、評価結果、講義内容との対応、今後の課題が書かれている。
    AC-09README の手順に従うと、新しい環境でシミュレーションと評価を再現できる。

    09
    v2: 実機で SmolVLA と比べる
    v1 の IK による実行部分を、実機で収集したデモで微調整した SmolVLA に差し替え、同一条件で比較する。
    
      
    
        
    
          
          
    人が見せたお手本 50 本(暫定)を、品質チェック(欠けたフレーム・時刻のずれ・範囲外の値)に通してから学習に使う。RoboOps ワークショップの「データ検証」を使う部分。
    
        
    
        
    
          
    v2 機能要件5 件
    ID要件
    FR-V2-01システムは、実機の SO-101 を So101Robot 経由で動かし、v1 と同じ指示で pick & place を実行できなければならない。
    FR-V2-02システムは、遠隔操作によるデモを LeRobot 形式で記録できなければならない。デモには、カメラ画像、関節状態、行動、言語指示を含める。遠隔操作には SO-101 のリーダーアームを使う(LeRobot のテレオペ機能)。
    FR-V2-03システムは、収集したデモで SmolVLA を微調整し、Policy インターフェースの実装として読み込めなければならない。
    FR-V2-04システムは、IK 版と SmolVLA 版を、同じ指示・同じ初期配置の範囲で実機評価し、成功率と所要時間を出力しなければならない。
    FR-V2-05システムは、デモの品質(欠損フレーム、時刻のずれ、関節値の範囲外)を学習前に検証し、不合格のデモを除外しなければならない(RoboOps ワークショップの内容)。
    
          
    v2 非機能要件3 件
    ID要件
    NFR-V2-01実機の安全要件 NFR-07 を満たす。
    NFR-V2-02微調整の設定(データセット、ハイパーパラメータ、シード)を設定ファイルに残し、再現できる。
    NFR-V2-03実機のシリアルポート(フォロワー・リーダーの2本)とカメラは udev で固定名にする(第3回の内容)。
    
          
    v2 受け入れ基準4 件
    ID基準
    AC-V2-01デモを 50 本(暫定)以上収集し、検証を通過したものだけで微調整できている。
    AC-V2-02実機で IK 版と SmolVLA 版をそれぞれ 10 回(暫定)試行し、成功率と所要時間の比較表をレポートに載せる。
    AC-V2-03SmolVLA 版の実機での成功率 50% 以上(暫定目標)。満たさない場合も、失敗の分析をレポートに載せれば v2 完了とする。
    AC-V2-04試行中に非常停止が機能することを、実機で 1 回以上確認している。

    リスク対応
    把持が不安定大きめのブロック、摩擦・グリッパーの調整から始める
    VLM の座標精度が低い検出の枠で出力させ、中心を取る。失敗時は再試行
    API 利用料・応答時間1試行1回の呼び出しに抑える。結果をキャッシュして再現実験を可能にする
    プロバイダ間で座標精度・出力形式が異なる共通スキーマと JSON 検証で吸収する。比較結果はレポートに記載する
    Gemma は小型だと検出精度が低い可能性、画像非対応のサイズがある画像に対応するサイズを Ollama のモデル一覧で確認して選ぶ。モデルサイズを設定で選べるようにし、精度を実測する。低い場合は比較表に限界として記載する
    ローカルモデルが Mac のメモリに収まらない小さいサイズに下げる。使用メモリを実測して記録する
    モデル名・API 仕様の変更モデル名はコードに固定せず設定ファイルに置く。実装前に各公式ドキュメントで確認する
    実機とのずれ座標変換を calibration として分離する
